## 0. 원본 시스템에서 바꾼 것

원본은 **마케팅 페이지용**이었고 이 서비스는 **업무 화면**이다. 세 가지를 바꿨다.

| 항목 | 원본 | 이 시스템 | 이유 |
|---|---|---|---|
| 주색 | 오버진 `#4a154b` | **블루 `#0070eb`** | 시안 기준. 사내 도구의 중립적 신뢰감 |
| 버튼 기하 | 필 90px | **둥근 사각 10px** (원형 아이콘 버튼만 예외) | 시안 기준. 정보 밀도가 높은 화면에 맞음 |
| 히어로 그래디언트 | 모든 히어로 밴드 | **쓰지 않음** | 원본도 "transactional pages에서는 그래디언트를 뺀다"고 명시 |

**웹폰트는 CDN에서 불러오지 않는다.** 폐쇄망 전제이므로 폰트 한 줄 때문에 외부 통신이
생기면 안 된다. 시스템 스택으로 두고, 운영 전환 시 파일로 반입해 self-host 한다
(온프렘 설계서 §5).

## 1. 색

시안에서 직접 추출한 값이다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--primary` | `#0070eb` | 로고, 채워진 버튼, 활성 탭 글자, 체크 완료, 조문 강조 |
| `--primary-press` | `#005cc4` | 눌림 상태 |
| `--primary-tint` | `#e1efff` | 활성 탭 배경, 문서 아이콘 배경, 배지 |
| `--primary-tint-2` | `#f0f7ff` | 고지 블록, 모드 배지 |
| `--canvas` | `#f8f9fb` | 페이지 바탕 |
| `--surface` | `#ffffff` | 카드 |
| `--fill` | `#f1f3f6` | 입력 채움, 보조 카드, 고스트 버튼 |
| `--hairline` | `#e8eaee` | 카드 테두리, 구분선 |
| `--ink` / `--ink-mute` / `--ink-faint` | `#1a1d21` / `#6a6f77` / `#9aa0a8` | 본문 / 보조 / 흐린 |
| `--error` / `--success` | `#d64545` / `#0a8a5f` | 오류 / 성공 |

**주색은 아껴 쓴다.** 한 화면에 채워진 파란 버튼은 하나(로그인 / 보내기)만 둔다.
나머지 동작은 `--fill` 고스트 버튼이나 `--primary-tint` 칩으로 처리한다.

## 2. 타이포

시스템 스택(`Pretendard` → `Inter` → OS 기본). 본문 15px / 1.6.

| 용도 | 크기 | 굵기 | 자간 |
|---|---|---|---|
| 페이지 제목 (`h1`) | 27px | 700 | -0.4px |
| 대화 시작 인사 | 26px | 700 | -0.4px |
| 섹션 제목 (`h2`) | 18px | 700 | -0.2px |
| 본문 | 15px | 400 | 0 |
| 카드 제목 | 14.5px | 600 | 0 |
| 보조 설명 | 14px | 400 | 0 |
| 라벨·메타 | 12.5~13px | 600 | 0 |

## 3. 기하

| 토큰 | 값 | 용도 |
|---|---|---|
| `--r-sm` | 8px | 칩, 배지, 문서 아이콘 |
| `--r-md` | 10px | 버튼, 입력, 보조 카드 |
| `--r-lg` | 14px | 카드 |
| `--r-pill` | 999px | 로고, 원형 버튼, 입력창, 체크박스 |

간격은 8px 기준 (`4 / 8 / 12 / 16 / 20 / 24 / 32`).
그림자는 두 단계뿐이다 — 카드용 미세 그림자, 떠 있는 요소용 그림자.

## 4. 컴포넌트

| 이름 | 설명 |
|---|---|
| `btn-primary` | 채워진 파란 버튼. 화면당 하나 |
| `btn-ghost` | 회색 채움 보조 버튼. 아이콘 + 라벨 |
| `chip-btn` | 파란 틴트 칩. 답변 안의 "담기" |
| `round-btn` | 원형 아이콘 버튼. 답변 옆 북마크 |
| `quick button` | 가로 꽉 찬 질문 카드 + 우측 화살표 |
| `row-card` / `row` | **항목을 각각의 카드로 흩지 않고 한 카드 안에 행으로** 담는다 |
| `subcard` | 답변 안의 회색 보조 카드 (해야 할 일, 근거 발췌) |
| `doc-chip` | 참고 문서 칩 (문서 아이콘 + 제목) |
| `empty-card` | 빈 상태. 가운데 아이콘 + 한 줄 안내 |
| `pill-badge` | "사내 문서 기반 답변" 같은 눈썹 배지 |

## 5. 화면 구조

**상단바** — 로고 배지 + 서비스명 / 아이콘 탭 4개 / 사용자 이름·소속 / 로그아웃.
활성 탭은 파란 틴트 배경.

**로그인** — 380px 폭, 그림자 없는 평면. 입력은 테두리 없이 회색 채움.

**대화 시작** — 눈썹 배지 → **이름을 부르는 인사** → 안내 한 줄 → 질문 카드 5장 → 입력창.
첫 질문이 들어오면 시작 안내는 사라진다.

**답변** — 흰 카드에 5단 구조. 참고 문서는 칩, 해야 할 일과 근거 발췌는 회색 보조 카드.
저장 버튼은 카드 옆에 원형으로 떠 있어 본문을 방해하지 않는다.

**목록 화면(할 일·저장한 답변·문서)** — 제목 + 상태 한 줄(`3개 중 1개 완료했어요`) + 행 카드.

## 6. 문장 톤

시안을 따라 **"~해요" 체**를 쓴다. 사내 도구지만 신규 입사자가 처음 만나는 화면이다.

- ✅ `열람 권한이 있는 문서 12건이에요.` / `아직 저장한 답변이 없어요.`
- ❌ `열람 권한이 있는 문서는 12건입니다.` / `저장된 항목이 없습니다.`

단, **고지·경고는 격식체를 유지한다.** 법정 기준 안내나 민감정보 차단 문구까지 부드럽게
쓰면 무게가 사라진다.

## 7. 하지 말 것

- 세 번째 강조색을 추가하지 않는다. 파랑 + 회색조로 충분하다.
- 한 화면에 채워진 파란 버튼을 둘 이상 두지 않는다.
- 목록 항목을 각각 그림자 있는 카드로 흩지 않는다. 한 카드 안의 행으로 담는다.
- 웹폰트·아이콘을 외부 CDN에서 불러오지 않는다. 아이콘은 인라인 SVG 심볼로 둔다.
- 동적 텍스트를 `innerHTML`로 넣지 않는다. 아이콘도 `createElementNS`로 만든다.
