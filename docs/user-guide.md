- 로그인에 비밀번호를 도입했습니다. 사번은 선택, 비밀번호는 **서버에서 검증**합니다 (§1)

- 북마크를 없앴습니다. 저장한 답변이 근거 문서와 발췌를 이미 담고 있어 역할이 겹쳤습니다
- 저장한 답변을 펼치면 저장 당시의 5단 구조 전체를 다시 볼 수 있습니다 (§4.E)

**v1.1 주요 변경**

- 프로토타입 환경과 목표 운영 환경의 구분을 명시했습니다 (§0)
- **개인 데이터 저장 정책을 전면 개정했습니다.** 북마크·저장한 답변·체크리스트 진행 상태는 저장하며, 민감 원본 데이터와 실제 제출 파일은 저장하지 않습니다 (§4)
- 화면 목록과 상태 전이를 추가했습니다 (§7)
- 개인화 원칙의 상세는 온프레미스 설계 문서 4장을 단일 출처로 참조하도록 정리했습니다

## 0. 이 챗봇이 지금 어떤 환경에서 동작하는지

이 프로젝트는 두 가지를 **각각 다른 방식으로** 증명합니다.

| | 프로토타입 (지금 보시는 것) | 목표 운영 환경 |
|---|---|---|
| 증명 방식 | **실행되는 시연** | **설계 문서** ([온프레미스 설계 문서](../onpremise-setup/onpremise-setup.md)) |
| 지식 데이터 | 합성 온보딩 문서만 | 승인된 실제 사내 문서 |
| 사용자 정보 | 가상 프로필 4명 | 사내 인사 시스템의 최소 속성 |
| 로그인 | 사번 선택 + 데모 비밀번호 (서버 검증) | 사내 SSO |
| 답변 생성 | 문서 근거를 정리하는 방식 | 사내 LLM 추론 서버 |
| 외부 LLM API 호출 | 없음 | 없음 |

프로토타입은 합성 문서만 사용하므로 **실제 사내 데이터가 외부로 나가지 않습니다.**
화면 상단에 항상 아래 배지가 표시됩니다.

```
[프로토타입 데모] 합성 문서 기반 · 외부 LLM API 미사용 · 실제 사내 데이터 없음
```

## 1. 챗봇을 여는 방법

### 접근 경로

사내 포털 또는 사내망 전용 URL에서 챗봇을 엽니다. 외부 메신저, 개인 계정, 외부 AI 서비스에 사내 문서나 질문을 입력하지 않습니다.

```text
사내 포털 로그인
  → "온보딩 도우미" 메뉴 선택
  → 챗봇 화면 열기
  → 질문 입력 또는 빠른 질문 선택
  → 근거 문서와 다음 행동 확인
```

### 로그인이 필요한 이유

챗봇은 **로그인 없이 사용할 수 없습니다.** 선택 사항이 아니라 필수이며, 이유는 두 가지입니다.

- **권한에 맞는 문서만 검색하기 위해서입니다.** 로그인이 없으면 어떤 문서를 보여줄 수 있는지 판단할 수 없습니다.
- **개인 상황에 맞는 안내를 하기 위해서입니다.** 건강검진 대상 여부는 입사 시점에서 계산되므로, 누구인지 모르면 답할 수 없습니다.

해커톤 데모에서는 사내 SSO 대신 **사번 선택 + 비밀번호** 화면을 사용합니다. 사번은 가상 사용자 중에서 고르고, 비밀번호 초기값은 화면 하단에 안내됩니다.

> **비밀번호는 서버에서 검증합니다.** 브라우저 코드에는 비밀번호가 들어 있지 않습니다.
> 데모용 고정 비밀번호이므로 실제 인증은 아니지만, 검증이 일어나는 위치는 운영 환경과 같습니다.

### 세션

로그인하면 서버가 세션을 만들고 브라우저에 세션 식별자를 내려줍니다. 세션은 두 가지 역할을 합니다.

- **매 질문마다 사용자를 다시 확인합니다.** 브라우저에서 사번을 바꿔도 다른 사람의 권한을 얻을 수 없습니다.
- **최근 대화 맥락을 유지합니다.** "그럼 언제까지예요?" 같은 후속 질문을 직전 질문과 연결해 이해합니다.

세션은 30분 동안 활동이 없으면 종료됩니다. 세션이 끝나도 **저장한 항목(§4)은 남습니다.**

## 2. 화면별 역할

| 화면 | 사용자 | 하는 일 |
|---|---|---|
| 직원 화면 | 신규·경력 입사자 | 질문하고, 허용된 문서를 확인하고, 저장한 답변과 할 일을 관리합니다 |
| 인사담당자 화면 | 인사담당자 | 승인된 문서를 등록·검토·발행하고, 품질 피드백을 확인합니다 |
| 관리자 화면 | 시스템 관리자 | 권한·운영 상태·감사 정보를 최소 범위에서 확인합니다 |

## 3. 직원용 화면

### A. 시작 화면

- 환영 문구와 이용 안내
- 빠른 질문 버튼 — 입사 서류 제출 / 필수 교육과 인수인계 / 비품 신청과 전자결재 / 건강검진 / 연말정산
- 안내 문구: "이 챗봇은 승인된 사내 문서를 근거로 안내하며, 실제 신청·예약·제출을 대신하지 않습니다."

### B. 대화 화면

답변은 항상 아래 순서로 표시됩니다. 내용이 없는 항목은 생략되지만 **순서는 바뀌지 않습니다.**

1. **한 줄 요약** — 질문에 대한 핵심 답변
2. **해야 할 일** — 제출물, 확인 순서, 기한
3. **참고 문서** — 문서명, 버전, 갱신일, 인용 구간 *(생략되지 않습니다)*
4. **주의·예외** — 개인별 확인이 필요하거나 정책이 달라질 수 있는 경우
5. **담당 부서** — 사내 시스템 이동 또는 문의처

각 "해야 할 일" 항목 옆에 **[할 일로 담기]** 버튼이, 답변 아래에 **[이 답변 저장]** 버튼이 있습니다 (§4).

### C. 외부 절차 안내

- **건강검진** — 지정 병원 사이트를 새 페이지로 여는 링크만 제공합니다. 챗봇 안에서 예약·로그인·결제를 하지 않습니다.
- **연말정산** — 홈택스에서 진행해야 한다는 안내와 새 페이지 링크만 제공합니다. 챗봇 안에서 로그인·자료 제출을 하지 않습니다.
- 링크를 누르기 전에 외부 사이트로 이동한다는 안내가 표시됩니다.

### D. 개인화 안내 표시

챗봇은 입사 시점·고용 상태 같은 **최소한의 속성**으로 안내를 나눕니다.

- 개인 원본값 대신 **판정 결과만** 보여줍니다 — 예: "현재 입사 시점 기준으로 건강검진 대상이 아닙니다"
- 사번은 `12****`, 이메일은 `ho***@example.com` 로 마스킹합니다
- **어떤 조건으로 판정했는지 한 줄로 밝힙니다** — 예: "판정 근거: 2026년 입사 · 조회 연도 2026년"
- 개인화 판정에 사용하는 속성의 상세 목록과 처리 원칙은 [온프레미스 설계 문서](../onpremise-setup/onpremise-setup.md) 4장을 따릅니다

## 4. 무엇이 저장되고, 무엇이 저장되지 않는가 ★

> **원칙:** 사용자가 **직접 저장을 선택한 것**은 저장합니다. 민감 원본 데이터와 실제 제출 파일은 저장하지 않습니다.

### A. 저장되는 항목

| 항목 | 저장 내용 | 목적 |
|---|---|---|
| **저장한 답변** | 질문, 답변 5단 구조 전체(요약·해야 할 일·근거 문서·발췌·주의), 저장 시각 | 나중에 **답변 그대로** 다시 보기 위해서입니다 |
| **내 할 일** | 항목 내용, 출처 문서 ID·버전, 완료 여부, 완료 시각 | 온보딩 진행 상황을 스스로 관리하기 위해서입니다 |

> 북마크(문서 구간 저장)는 두지 않습니다. 저장한 답변이 이미 근거 문서와 원문 발췌를 담고 있어
> 역할이 겹쳤고, 사용자가 두 기능의 차이를 구분할 이유가 없었습니다.

저장한 항목은 로그아웃하거나 세션이 끝나도 유지되며, 다음에 로그인하면 그대로 있습니다.

### B. 저장되지 않는 항목

| 항목 | 이유 |
|---|---|
| 주민등록번호, 신분증 번호, 계좌번호, 카드번호 | 민감 원본 데이터입니다 |
| 비밀번호, 임시 비밀번호, 인증번호 | 인증 정보입니다 |
| 건강검진 결과, 진단 내용 등 건강 정보 | 민감정보입니다 |
| **실제 제출 파일** (통장 사본, 신분증 사본 등) | 챗봇은 파일 업로드를 받지 않습니다. 실제 제출은 사내 포털에서 합니다 |
| 급여·인사 평가 정보 | 별도의 접근 통제 시스템에서 관리합니다 |

### C. 저장 전 검사

저장 버튼을 눌러도, 저장하려는 내용에 위 민감 항목이 포함되어 있으면 **저장되지 않고 안내가 표시됩니다.**

> 저장하려는 내용에 민감정보로 보이는 값이 포함되어 있어 저장하지 않았습니다.

### D. 저장한 항목의 취급

- **본인만 조회할 수 있습니다.** 다른 직원은 물론 인사담당자·관리자도 열람할 수 없습니다.
- **언제든 삭제할 수 있습니다.** `내 저장함`에서 개별 삭제 또는 전체 삭제가 가능합니다.
- **자동 수집과는 다릅니다.** 품질 개선을 위한 자동 로그에는 질문 원문이 남지 않습니다. 사용자가 명시적으로 저장한 항목만 원문이 보관됩니다.
- **문서가 갱신되면 표시됩니다.** 저장한 답변이나 할 일의 출처 문서가 새 버전으로 바뀌면 아래 안내가 붙습니다.

  > 출처 문서가 v1.1로 갱신되었습니다. 내용을 다시 확인해 주세요.

### E. 저장한 답변 다시 보기

`저장한 답변` 탭에서 질문 제목 옆 **[펼치기]** 를 누르면 저장 당시의 답변 전체가 다시 표시됩니다.
요약, 해야 할 일, 근거 문서와 원문 발췌, 주의·예외까지 그대로입니다.

근거 문서가 새 버전으로 갱신되었으면 카드에 안내가 붙습니다.

> 근거 문서가 갱신되었습니다 (입사 서류 제출 안내 v1.1). 내용을 다시 확인해 주세요.

### F. 내 할 일 사용법

1. 답변의 **해야 할 일** 항목 옆 **[할 일로 담기]** 를 누릅니다.
2. `내 할 일` 탭에서 전체 항목과 진행 상태를 확인합니다.
3. 완료한 항목을 체크합니다.

탭에는 **완료하지 않은 항목 수**가 표시되고, 마지막으로 그 탭을 본 뒤 새로 담긴 항목에는
**New** 배지가 붙습니다. 탭을 열어보면 New 표시는 사라집니다.

> **주의:** 내 할 일은 **본인이 관리하는 메모**입니다. 여기에 체크했다고 실제 제출·신청이 완료된 것은 아닙니다. 실제 처리 여부는 사내 포털에서 확인해 주세요.

## 5. 질문하는 방법

### 좋은 질문 예시

- "입사 서류로 무엇을 제출해야 하나요?"
- "사무용품은 어디에서 신청하나요?"
- "저는 올해 입사했는데 건강검진은 언제 확인하면 되나요?"
- "이직자인데 연말정산에서 이전 회사 자료도 확인해야 하나요?"
- "전자결재 문서가 반려되면 어떻게 하나요?"

### 입력하면 안 되는 정보

- 비밀번호, 임시 비밀번호, 인증번호
- 주민등록번호, 신분증 번호, 계좌번호, 카드번호
- 본인의 건강검진 결과·진단 내용
- 타인의 개인정보, 급여·인사 평가 정보
- 외부 반출이 금지된 사내 기밀 원문

민감정보가 감지되면 챗봇은 입력을 처리하지 않고 안내합니다. 해당 내용은 저장되지 않습니다.

> **참고:** "건강검진은 언제 받나요?", "검진 결과가 회사에 공유되나요?" 같은 **제도 문의는 정상적으로 처리됩니다.**
> 차단되는 것은 본인이나 타인의 실제 건강 정보를 입력하거나 요청하는 경우입니다.

## 6. 답변을 신뢰하는 방법

챗봇의 모든 안내는 다음을 만족합니다.

- 답변에 **참고 문서와 버전**이 표시됩니다.
- 문서 근거가 부족하면 "확인할 수 없다"고 말하고 인사팀으로 연결합니다.
- 최신성이나 개인별 예외가 중요한 내용은 "확인 필요"를 명확히 표시합니다.
- 정책이 변경되면 새 문서 버전을 근거로 답변합니다.
- 참고 문서 간 안내가 서로 다르면 판단하지 않고 양쪽을 모두 보여준 뒤 담당 부서로 안내합니다.

### 답변이 맞지 않거나 부족한 경우

1. 답변 아래의 `정확하지 않아요` 또는 `도움이 필요해요`를 선택합니다.
2. 선택 사유를 남깁니다. 개인정보는 입력하지 않습니다.
3. 챗봇이 근거 문서와 함께 인사팀 문의 경로를 안내합니다.
4. 인사담당자가 피드백을 검토해 문서를 보완하거나 새 버전을 발행합니다.

## 7. 화면 목록과 상태

### A. 화면 목록

| 화면 | 대상 | 주요 요소 |

| 대화 | 직원 | 질문 입력, 빠른 질문, 5단 답변, [할 일로 담기]·[이 답변 저장] 버튼 |
| 저장한 답변 | 직원 | 저장 목록, 펼쳐서 전체 보기, 갱신 안내, 개별·전체 삭제 |

| 문서 목록 | 직원·인사담당자 | 권한 범위 내 문서, 카테고리·버전·유효기간 |
| 문서 편집 | 인사담당자 | 제목·본문·카테고리·대상·유효기간·담당부서, 데모 가정 배지 |
| 검토·발행 | 인사담당자 | 변경 전후 비교, 승인자, 미리보기, 롤백 |
| 품질 대시보드 | 인사담당자 | 자주 묻는 질문, 근거 부족 응답, 부정확 피드백, 만료 임박 문서 |

### B. 문서 상태 전이 (인사담당자)

```text
[초안] ──제출──▶ [검토중] ──승인──▶ [발행] ──유효기간 경과──▶ [만료]
   ▲                  │                 │                        │
   └──────반려─────────┘                 └────새 버전 발행────────▶[대체됨]
                                          │
                                          └──긴급 비활성화──▶ [보류]
```

| 상태 | 챗봇 검색 대상 | 설명 |
|---|---|---|
| 초안 | ❌ | 작성 중. 검색에 절대 포함되지 않습니다 |
| 검토중 | ❌ | 승인 대기 |
| 발행 | ✅ | 검색 가능 |
| 만료 | ❌ | 유효기간 경과. "최신본 확인 필요"로 안내 |
| 대체됨 | ❌ | 새 버전이 대신합니다 |
| 보류 | ❌ | 오류·민감정보 노출 의심으로 즉시 비활성화된 상태 |

승인 없이는 어떤 문서도 검색에 포함되지 않습니다. 운영 환경에서는 작성자와 승인자를 분리합니다.

## 8. 역할별 접근 범위

| 역할 | 볼 수 있는 것 | 할 수 없는 것 |
|---|---|---|
| 직원 | 공통 온보딩 문서, 소속 부서에 허용된 문서, 마스킹된 본인 상태, **본인의 저장한 답변·할 일** | 타인 정보 조회, 문서 발행, 실제 신청 대행 |
| 인사담당자 | 승인 권한에 맞는 문서, 품질 피드백, 최소 운영 정보 | 승인 없는 문서 발행, **직원 개인의 저장 항목 열람**, 불필요한 개인정보 열람 |
| 관리자 | 시스템 상태, 권한 설정, 최소 감사 정보 | 업무상 필요 없는 문서·개인정보 열람, **직원 개인의 저장 항목 열람** |

> 권한은 문서 소속(부서)과 역할 양쪽으로 판정합니다. **관리자라고 해서 모든 문서를 볼 수 있는 것은 아닙니다.**
> 예를 들어 인사담당자는 인사평가 문서를 볼 수 있지만, 개발팀 전용 문서는 볼 수 없습니다.

## 9. 해커톤 데모 시나리오

### 시나리오 1 — 신규 입사자

- 가상 사용자 `123456`(개발팀, 2026년 입사)으로 접속합니다.
- 건강검진을 질문하면 "입사 당해 연도는 대상이 아니며 다음 해부터 대상"이라는 개인화된 안내와 문서 근거가 표시됩니다.
- 답변의 "해야 할 일"을 [할 일로 담기]로 담고, 답변 전체를 저장합니다.

### 시나리오 2 — 이직 경력 입사자

- 가상 사용자 `345678`(개발팀, 2026년 이직 입사)으로 접속합니다.
- 연말정산을 질문하면 이전 회사 원천징수영수증 확인 항목이 추가로 표시됩니다.
- 건강검진을 질문하면 비대상 안내와 함께 "이전 직장 수검 여부 확인 필요" 표시가 붙습니다.

### 시나리오 3 — 권한이 다른 두 사용자, 같은 질문 ★

- `123456`(개발팀)과 `234567`(영업팀)이 **같은 질문**을 합니다 — "개발팀 인수인계는 어떻게 진행하나요?"
- 개발팀 사용자는 답변을 받고, 영업팀 사용자는 "확인 가능한 문서 근거가 충분하지 않습니다"를 받습니다.
- 챗봇은 **문서가 존재한다는 사실 자체를 알려주지 않습니다.**

### 시나리오 4 — 인사담당자

- 가상 인사담당자 `901234`가 연말정산 가이드의 새 버전을 발행합니다.
- 챗봇이 새 문서 버전을 근거로 답변하는 것을 확인합니다.
- 이 사용자도 개발팀 전용 문서는 볼 수 없습니다.
