# 개발팀 온보딩·인수인계 가이드

> **데모용 가정 안내:** 이 문서는 소속 기반 권한 통제 시연을 위한 가상 문서입니다. 실제 개발팀의 절차가 아닙니다.
>
> **열람 범위:** 이 문서는 개발팀 소속(`dept:개발팀`) 구성원만 열람할 수 있습니다. 다른 부서 구성원의 질문에는 검색 결과에 포함되지 않습니다.

## 첫 주 온보딩 순서

1. 개발 계정을 발급받습니다. 형상관리, 이슈 트래커, 사내 위키 계정이 함께 생성됩니다.
2. 개발 환경 설정 문서를 따라 로컬 환경을 구성합니다.
3. 온보딩 담당 선임과 첫 미팅을 진행합니다.
4. 담당하게 될 서비스의 아키텍처 개요를 확인합니다.
5. 첫 과제로 소규모 이슈를 배정받아 배포까지 한 사이클을 경험합니다.

## 인수인계 자료

인수인계를 받을 때 아래 자료를 확인합니다.

| 자료 | 확인 내용 |
|---|---|
| 서비스 개요 문서 | 담당 서비스의 역할과 주요 흐름 |
| 저장소 목록 | 접근 권한이 필요한 저장소와 브랜치 전략 |
| 배포 절차서 | 배포 방식, 승인 절차, 롤백 방법 |
| 운영 대응 문서 | 장애 등급, 대응 순서, 연락 체계 |
| 미해결 이슈 목록 | 인계 시점의 진행 중 과제와 우선순위 |

## 인수인계 담당자 확인

인수인계 담당자는 부서장이 지정합니다. 담당자가 지정되지 않았다면 개발팀 리더에게 문의합니다.

## 코드 리뷰 규칙

- 모든 변경은 리뷰를 거쳐 병합합니다.
- 리뷰어는 최소 1명을 지정합니다.
- 보안에 영향을 주는 변경은 리뷰어를 2명 이상 지정합니다.
- 외부 패키지를 새로 추가할 때는 취약점 점검 결과와 유지보수 상태를 함께 기재합니다.

## 배포

- 배포는 배포 절차서에 정의된 방식으로만 진행합니다.
- 운영 환경 배포는 사전 승인을 받은 뒤 진행합니다.
- 배포 후에는 지표와 오류 로그를 확인합니다.

## 주의 사항

- 사내 저장소의 코드와 설정을 외부에 반출하지 않습니다.
- API 키와 비밀값은 저장소에 커밋하지 않고 환경변수로 관리합니다.
- 개인 계정으로 사내 서비스에 접근하지 않습니다.

## 자주 묻는 질문

**개발팀 인수인계는 어떻게 진행하나요?**
부서장이 지정한 인수인계 담당자와 함께 서비스 개요, 저장소 목록, 배포 절차서, 운영 대응 문서, 미해결 이슈 목록을 순서대로 확인합니다.

**첫 과제는 언제 배정되나요?**
개발 환경 구성과 온보딩 미팅이 끝난 뒤 소규모 이슈로 배정됩니다.
